# Deterministic versus live network tests

The default headless suite fixtures exactly one optional external endpoint: GitHub's `.../releases/latest`, returning `{tag_name: 'v0.3.0'}`. This removes an unrelated public-IP rate limit from scene/cancellation tests. Their strict console/page-error assertions are unchanged. Broad asset-interception handlers delegate unrelated requests with `route.fallback()`, so they do not bypass this fixture with `route.continue()`. Other HTTP failures still fail those tests.

Download and release-fallback tests override this boundary for successful tags, a missing tag, HTTP 403/404/429, and failed requests. Negative lookup tests permit only Chromium's autogenerated resource error with the exact expected status and exact release endpoint URL; genuine application errors remain failures. Unit tests also cover malformed JSON, offline failure, and caller abort. Production already catches optional lookup failures, retains the packaged version and continues scene operation; no production request, rate limit, or error logger was bypassed to make tests green.

`OV_LIVE_RELEASE=1 npx playwright test tests-e2e/release-live.spec.ts` is a separate opt-in observation. It does not fixture GitHub. Its attached status distinguishes an HTTP 200 lookup from an unavailable/rate-limited lookup with working scene operations. A default fixture pass is not a live-network pass. The previous box-network 403 remains recorded in the audit evidence; do not run repeated live retries to work around it.

A preview can use a separate build directory while another build is under manual QA. For example: `npx vite build --outDir ../build-next --emptyOutDir`, then `node scripts/check-precache.mjs ../build-next`. The default `npm run build` continues to target `dist`. Never rebuild an output directory pinned for an operator's QA session.
